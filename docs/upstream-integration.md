# First ACC dev integration increment

Candidate: v1.0.4-ng (202610094), unreleased. Based on NG 3d2dbe2 and ACC
v2023.10.16. The reviewed upstream endpoint is 908a5a4; this is not a merge
of that branch. NG API 1 and configuration schema 202310160 stay unchanged.

The full review, per-commit decisions and pending work are maintained in
[AccA-NG docs](https://github.com/ricardojrgpimentel/ACCA-NG/blob/main/docs/acc-upstream-roadmap.md).

| Origin | Applied scope | Remaining scope |
| --- | --- | --- |
| 39a2208, 4b1bfd4 | Restore current/voltage/thermal controls only when owned, once; snapshot actual values | Live OEM control and upgrade validation |
| eaa0c4d | Separate setters from other limits and boot/plug scripts | Remaining daemon-loop optimisations |
| 4999c63 | Replace forced ownership/world-write changes with direct write then temporary u+w and restoration | Live sysfs permission validation |
| 69cfecb | Exclude store_mode from built-in automatic candidates | Upstream release metadata intentionally replaced by NG |

`install/limit-control.sh` serialises each kind of limit with a five-second
flock budget, retains snapshots for failed resets and reports failed readback.
An unchanged refused write does not acquire ownership; a changed node with
failed readback retains its snapshot for recovery. Snapshots live in the
volatile runtime directory and persist across daemon restarts within a boot.
Resetting an absent snapshot does not discover sensors or wait for a charger.
Manual/plugin switch overrides are preserved.

Test with:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
ACC_TEST_ADB_SERIAL=<serial> PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_limits.py -v
```

The opt-in Android runner uses root, mksh and the installed BusyBox. It writes
only generated files below /data/local/tmp and removes them after each test.
Host tests shim platform-specific tools; real lock contention tests require
Android. No module installation or real charging-control writes are part of
these fixtures. Before release, validate upgrade/rollback, live controls and
OEM thermal behaviour. Frontend confirmation of actual hardware application
(R1.4), broader sensor discovery, migrations and optional features remain pending.

## I2 — R0 frontend contract and fixtures

Candidate: **v1.0.5-ng (202610095)**, unreleased, built on I1 `7375bbb`.
The reviewed upstream endpoint remains `908a5a4`; this increment does not claim
additional upstream commits as fully ported. API 1 and schema 202310160 remain.

- R0.1: shared version, daemon status, default/current config, switch list and
  switch-result fixtures generated by executing production shell fragments.
- R0.2: explicit `ngConfigSchema` and `ngCapabilities` in module metadata.
  Capabilities describe API features; they do not certify hardware support.
  Old API 1 metadata preserves the fixed baseline without inventing capabilities.
- R0.3: profile writes and reloads preserve six capacity elements, the r suffix,
  manual switch, calibration and global notification preferences. App fixtures
  also cover legacy database JSON and modern profile serialization.
- R0.4: host/Android synthetic sensors exercise positive/negative current,
  zero, missing/malformed/refused readings and mA/µA, mV/µV. Discovery of actual
  OEM sensors, lifecycle upgrades and live hardware verification remain R2/R7.

`batt-info.sh` omits unavailable current/voltage and derived power instead of
fabricating valid zero measurements. This preserves the key/value API and units.
The fixture exporter records hashes of the production scripts; app CI checks
those hashes against the tarball it actually ships. The app also fixes parsing
of quoted switches/hooks, literal shell arguments, battery flag polarity and
independent CURRENT_QNOVO/CHARGE_DISABLE fields. Thermal semantics use the
schema contract rather than the NG release date, including in the config editor.

Validation on 9 October 2026: 52 host engine tests (50 passed, 2 Android-only
lock cases skipped); 17 contract cases on Samsung SM-G975F using root, mksh and
BusyBox. All writes use generated temporary files, never live sysfs. The
existing Android limit suite passed all 20 tests, and all 28 runtime scripts
passed `/system/bin/sh -n`.
No installed app, module, profile or charging configuration is updated by I2.

Still pending: R1.2 cache/discovery, R1.4 physical application readback,
R2 sensor/charger unification, and the physical upgrade/rollback/reboot matrix.


## I3 — discovery, incoming power and control readback

10 October 2026. Unreleased candidate **v1.0.6-ng (202610106)** over `2d969cb`.
The app's bundle provenance pins the final engine source commit.
API 1/schema 202310160 remain unchanged.

- R1.2: bounded discovery and cache per boot/type, strict numeric readings,
  original ownership snapshots, alias deduplication and explicit lack of support.
- R1.4: deferred offline requests and additive `power-limits-status` capability.
  `acca --power-status` reports requested value, support and state. Applied means
  nodes match after successful writes; drift/refused readback is failed.
- R2.1: final upstream acc -p blacklist, live candidate validation and thermal
  reference validation. No discovery chmod or fallback to arbitrary nodes.
- R2.4: external-power.sh is shared with events and generated Kotlin frontend.
  A connected source wins; incomplete sources do not prove disconnection.

The daemon applies the latest config under the frontend lock rather than
queuing setters which later rewrite an old profile. Saving automatic selection
re-reads config and respects a manual choice. Global atomic writes, imports and
legacy CLI concurrency remain R4. Explicit boot/plug scripts retain their flow.

Sources adapted: 07a3a8d/e89c463/486aa90/a74d83b (R1),
d8cf7bb/e00ba35/67ec354/52265a1/7784280/6b308d8 (R2.1).
Only the incoming-power part of mixed 9cdf64f is covered; polarity/optional
features remain R3/R6. New switches and alternative sensors remain R2.2/R2.3.

Synthetic Android tests use generated files under /data/local/tmp, never live
sysfs. A limited Samsung physical trial passed upgrade/config preservation and
readback of refused current writes; voltage discovery remained pending during
cooldown. The original config was restored. The app's I3 record identifies the
installed runtime and exact test scope, including an inherited staging cleanup
bug still open in R5.3. Actual limits/reset, OEM policy and the full rollback
matrix remain pending before distribution.
