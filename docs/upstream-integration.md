# First ACC dev integration increment

Candidate: v1.0.4-ng (202610094), unreleased. Based on NG 3d2dbe2 and ACC
v2023.10.16. The reviewed upstream endpoint is 908a5a4; this is not a merge
of that branch. NG API 1 and configuration schema 202310160 stay unchanged.

The full review, per-commit decisions and pending work are maintained in
[AccA-NG docs](https://github.com/ricardojrgpimentel/ACCA-NG/blob/main/docs/acc-upstream-roadmap.md).

| Origin | Applied scope | Remaining scope |
| --- | --- | --- |
| 39a2208, 4b1bfd4 | Restore current/voltage/thermal controls only when owned, once; snapshot actual values | Live OEM control and upgrade validation |
| eaa0c4d | Separate setters from other limits and boot/plug scripts | Remaining daemon-loop optimisations |
| 4999c63 | Replace forced ownership/world-write changes with direct write then temporary u+w and restoration | Live sysfs permission validation |
| 69cfecb | Exclude store_mode from built-in automatic candidates | Upstream release metadata intentionally replaced by NG |

`install/limit-control.sh` serialises each kind of limit with a five-second
flock budget, retains snapshots for failed resets and reports failed readback.
An unchanged refused write does not acquire ownership; a changed node with
failed readback retains its snapshot for recovery. Snapshots live in the
volatile runtime directory and persist across daemon restarts within a boot.
Resetting an absent snapshot does not discover sensors or wait for a charger.
Manual/plugin switch overrides are preserved.

Test with:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
ACC_TEST_ADB_SERIAL=<serial> PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_limits.py -v
```

The opt-in Android runner uses root, mksh and the installed BusyBox. It writes
only generated files below /data/local/tmp and removes them after each test.
Host tests shim platform-specific tools; real lock contention tests require
Android. No module installation or real charging-control writes are part of
these fixtures. Before release, validate upgrade/rollback, live controls and
OEM thermal behaviour. Frontend confirmation of actual hardware application
(R1.4), broader sensor discovery, migrations and optional features remain pending.

## I2 — R0 frontend contract and fixtures

Candidate: **v1.0.5-ng (202610095)**, unreleased, built on I1 `7375bbb`.
The reviewed upstream endpoint remains `908a5a4`; this increment does not claim
additional upstream commits as fully ported. API 1 and schema 202310160 remain.

- R0.1: shared version, daemon status, default/current config, switch list and
  switch-result fixtures generated by executing production shell fragments.
- R0.2: explicit `ngConfigSchema` and `ngCapabilities` in module metadata.
  Capabilities describe API features; they do not certify hardware support.
  Old API 1 metadata preserves the fixed baseline without inventing capabilities.
- R0.3: profile writes and reloads preserve six capacity elements, the r suffix,
  manual switch, calibration and global notification preferences. App fixtures
  also cover legacy database JSON and modern profile serialization.
- R0.4: host/Android synthetic sensors exercise positive/negative current,
  zero, missing/malformed/refused readings and mA/µA, mV/µV. Discovery of actual
  OEM sensors, lifecycle upgrades and live hardware verification remain R2/R7.

`batt-info.sh` omits unavailable current/voltage and derived power instead of
fabricating valid zero measurements. This preserves the key/value API and units.
The fixture exporter records hashes of the production scripts; app CI checks
those hashes against the tarball it actually ships. The app also fixes parsing
of quoted switches/hooks, literal shell arguments, battery flag polarity and
independent CURRENT_QNOVO/CHARGE_DISABLE fields. Thermal semantics use the
schema contract rather than the NG release date, including in the config editor.

Validation on 9 October 2026: 52 host engine tests (50 passed, 2 Android-only
lock cases skipped); 17 contract cases on Samsung SM-G975F using root, mksh and
BusyBox. All writes use generated temporary files, never live sysfs. The
existing Android limit suite passed all 20 tests, and all 28 runtime scripts
passed `/system/bin/sh -n`.
No installed app, module, profile or charging configuration is updated by I2.

Still pending: R1.2 cache/discovery, R1.4 physical application readback,
R2 sensor/charger unification, and the physical upgrade/rollback/reboot matrix.

## I6 — bounded probes, configuration transactions and lifecycle

Working candidate v1.0.8-ng (202610118), 11 October 2026, API 1 and schema
202310160. R2 discovery is combined with R3 bounded probes: 45 second total
budget, three consistent samples, exclusive test/daemon locks, exact control
journals, TERM cleanup and startup recovery after a killed probe. Manual
switches survive missing nodes; automatic candidate lists are snapshotted and
bounded, failed recovery returns 7. Polarity is learned over three successive
physical discharge samples without waiting for unplug. Thermal `r` only relaxes
thermal pauses, idle retries stop after two attempts, and cooldown waits inspect
sensors/unplug/shutdown every second.

R4 writers share the configuration mutex and commit a syntax-checked file by
rename, preserve extension assignments, escape hook quotes, retain last-good
and invalid sources, reject incompatible units and malformed values. Partial
raw-schema import accepts CRLF and replaces scripts by name. Scheduler stamps
are per command and calendar day, including midnight, preserving app DJS.

R5 exposes boot-aware engine-state without delaying status calls, respects
disable during bounded boot waiting and normal operation, records explicit
root manager flags and supports APatch BusyBox independently of detection.
Official manager references: https://kernelsu.org/guide/module.html and
https://apatch.dev/apm-guide.html. These document environment flags and BusyBox
paths; physical KSU/APatch certification remains pending.

Tarball/online installation uses private extraction directories and validates
one NG root, regular files/directories, paths, member count and total size.
Warnings from Android tar also reject unsafe absolute paths. Online downloads
require HTTPS, verified TLS, HTTP success and time/size limits. Rollback selects
a dated NG snapshot, validates it, atomically replaces the module and keeps the
current profile plus a backup of the replaced module. Diagnostic exports copy
bounded tails under an exclusive lock and include sensors, readiness, limits
and the latest switch result; failure export is asynchronous in the daemon.

Existing R6 safety: physical capacity remains the control/shutdown source;
presentation masks clamp to 0–100. Temporary `acc -f` uses a copy of the profile,
keeps OEM current/voltage and thermal limits, and returns to the regular daemon
on confirmed unplug. New optional idle_apps, Encore and percentage-current UI
remain outside this candidate, as permitted by R6's optional gate.

Host: 133 behavioral cases (131 passed, two Android-only cases skipped). The shared
source contract covers the added runtime helpers and both installers. Android,
app and physical candidate evidence is maintained in AccA-NG's
`docs/acc-ng-validation.md`; this source record does not certify unavailable
OEM devices/root managers or unsupported limit nodes.

Final compatibility audit also covers CLI `-s file` partial imports, `-c a`
case-insensitive named scripts (including names containing spaces), NG command
wrappers in schedules, comma-separated information/log filters, backup-version
readback and working-switch/support reports. Configuration validation does not
execute scripts; writer reload excludes script lines. A failing user hook does
not erase an otherwise valid profile. Unrelated dexopt jobs were removed from
the charging loop. Kernel/logcat capture is bounded in diagnostic exports.

### I6 Samsung input-pause correction

The Samsung `batt_slate_mode` OFF value also clears the external supply's
`online` bit while the cable remains attached. A readback marker for our own
OFF write now keeps that state unknown instead of asserting unplug. This
prevents false unplug/calibration events. A switch probe snapshots and briefly
enables the configured input control to prove external power, under the same
thermal checks and overall deadline. A separate durable journal restores the
original paused input after all probes, cancellation or daemon recovery.
The shared frontend helper resolves relative control paths against its supply
root. Native Not Charging readings still require battery-current confirmation
before being reported as idle.

The final CLI audit puts full config reset and script deletion under the same
atomic replacement/backup mutex; reset closes the writer lock before starting
a daemon so that the restarted process cannot inherit and retain it.

A physical locked-boot trial found that net discharge during boot could clear
the offMid request before applying the configured switch. The controller now
applies a known boot pause before requiring net charging, keeps an unresolved
request until automatic selection or leaving the interval, and retains the
shutdown-temperature guard. Behavioral fixtures cover both paths.
The boot-pause path forces the configured OFF write with bounded retries;
regular disable logic can treat net discharge as already stopped and skip it.
The regression executes the real retry helper so that a skipped write fails.


## I7 — retain loop cadence during confirmed unplug

12 October 2026. Candidate v1.0.9-ng/202610129, API 1/schema unchanged.
A physical I6 cable trial recorded real disconnect/reconnect and discharge,
but automatic polarity remained blank. The controller tried enabling charge
at resume capacity even when incoming power was explicitly absent. That could
spend 14 three-second ON-verification retries before the next polarity sample.

The discharge branch now skips that ON request for known disconnected power.
Unknown remains eligible for resume: an OEM's own input-cut must not prevent
re-enabling a selected switch. Shutdown, capacity and thermal evaluation retain
their existing paths. Controller-loop fixtures execute real is_charging/set_dp
functions and simulate the observed unpowered-switch wait. Before the fix,
three samples required 153 simulated seconds and three futile ON requests;
afterward they take 27 seconds and no ON request. Connected/unknown controls
remain eligible for resume and do not learn polarity as disconnected.

Physical evidence and final joint packaging are recorded in the app validation
record. The initial cable test passed connection detection only; it is not
relabeled as passing calibration. No release/updater metadata is promoted.

The ON verification itself also checks incoming power each retry. If unplug
happens after the request starts, it stops at the next three-second check rather
than waiting the full 42 seconds. Native battery status may lag and does not
prove charging after confirmed unplug. Separate fixtures verify that transition
and retain normal waits for connected/unknown power.
